# 06-wsl-dependency-check

Type: grilling
Status: resolved (2026-09-05, 三问菜单问答定稿)
Blocked by:

## Question

GUI 启动时（以及运行失败时）如何检测依赖链是否齐全，缺失时给用户什么样的可操作引导？

### 背景

目标场景是「换电脑或重装 WSL 后的自己」：GUI 点开就报 raw 错误最伤体验。依赖链自上而下：wsl.exe 存在 → Ubuntu 发行版已注册 → WSL 内 venv + 流水线脚本在位 → 三模型（whisper-large-v3 / CAM++ / Hy-MT2-7B）文件在位 → llama-server @8888 可达。

已具备的事实：02 定稿了 Windows 侧探测手段（wsl.exe 全路径调用、rc=255=WSL 层错误映射）；01 定稿了框架为 PySide6（可用 QMessageBox/QWizard 做引导 UI）。

待定：检测做在启动时一次性预检，还是只在出错时报？缺失时的引导形态（对话框分步指引？只读指引文档路径？要不要一键打开 PowerShell 帮装？）。检测粒度到哪层（要不要每次启动都探模型文件、探 8888 端口）。

## Answer

**定稿（2026-09-05 菜单问答）：轻检启动 + 全检转换 + 内嵌错误卡引导；预检清单含 8888 端口。**

### 三问三答

1. **检测时机：轻检启动 + 全检转换**（用户选推荐）
   - 启动时只查 wsl.exe 存在 + Ubuntu 已注册（实测 <1s）；缺失 → 主界面顶部黄条提示，不弹窗不打断。
   - 点「开始转换」时才全量预检（venv、三模型文件、8888 端口）；缺失 → 错误卡且不进入执行，避免白跑几分钟。
2. **引导形态：内嵌错误卡**（用户选推荐）
   - 复用 04 票 D 变体错误卡形态：缺什么 + 期望位置 + 修复参考命令 + 「复制诊断」按钮（汇总清单状态与关键路径入剪贴板）+「重试」。启动期轻检缺失用顶部黄条（04 原型的轻微扩展）。
3. **检测粒度：静态依赖；8888 端口自适应「换着用」**（用户两度强调「端口换换」，最终解读：**8888 被占用时自动换端口**，覆盖先前「端口也查查」的误读）
   - 全检清单（硬性失败项）：wsl.exe / Ubuntu 注册 / WSL 内 venv / whisper-large-v3 / CAM++ / Hy-MT2-7B 模型文件。
   - **端口策略（用户 2026-09-05 定）：8888 被占不是错误，换成一个不常用的随机端口**。理由（用户原话）：「最近 8888 附近好多都有人用」——顺延 8889/8890 属于重灾区，顺序探测不可靠。实施期改为：8888 上是本工具的 Hy-MT2 服务（按模型 id 校验）→复用；否则在 20000-32767（避开 ephemeral 段）随机选空闲端口拉起，冲突重试上限 5 次，翻译调用跟随实际端口（PORT 参数化贯穿 0/6 与 6/6）。
   - **复用防护**：`server_ready()` 现在只看 `/v1/models` 有响应——但本机 8888 常驻其他通用 llama-server 实例，必须加模型 id 校验（含 hy-mt2 才可复用），防止复用错误模型导致翻译悄悄劣化。
   - GUI 预检对端口降为**信息项**：显示「翻译服务运行中 @8888」或「8888 被占，将自动换端口」，不计入失败清单——端口问题由流水线自愈，GUI 不拦。

### 实施要点

- 轻检：wsl.exe 全路径存在 + `wsl.exe -d Ubuntu -- true` rc==0（02 票手段，rc=255 映射 WSL 层错误）。
- 全检：venv + 模型文件合并为**单次** wsl bash 调用（一条组合命令列文件并判存在），避免多次 WSL 调用开销。
- 端口自适应（宿主侧改造）：放弃 8888 中心制。`ensure_server()` 三分逻辑——8888 上是 Hy-MT2 服务（模型 id 校验）→复用；8888 被占/是别的服务→在 20000-32767 随机选空闲端口拉起（避开顺延段与 ephemeral 段，冲突重试上限 5 次）；翻译请求使用实际端口。`server_ready()` 加模型 id 校验。
- 诊断复制内容格式：逐项「✔/✘ 名称: 路径/状态」，附 WSL 发行版名与脚本路径、翻译服务实际端口。
